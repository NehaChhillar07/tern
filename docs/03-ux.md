## 1. Design direction

The brief is "less is more": the simplest interface that can do a counsellor's job.

- **Subject.** The Arctic tern flies the longest route of any animal. The product is about one long journey with fixed stops, so the single expressive element is the **route line**: a thin line with seven stops that shows where an application is, from Shortlisted to Enrolled. Everything else stays quiet.
- **Lists, not cards.** Courses, applications, checklist items and documents are rows separated by a hairline. No boxes inside boxes, no shadows.
- **One reading column,** left-aligned, at most 760px wide (680px in chat). A quiet sidebar holds four destinations.
- **Trust is the second signature.** Any fact with a dotted underline can be selected to show the exact sentence it came from, the page it is on and when it was last checked.

### Tokens

These become the shadcn theme (CSS variables). Nothing else may be hard-coded.

| Token | Light | Dark | Use |
|---|---|---|---|
| `paper` | `#FBFCFC` | `#0F171C` | Page background |
| `surface` | `#F1F4F6` | `#17222A` | User message, selected nav, source panel |
| `ink` | `#14212B` | `#E7EDF0` | Text |
| `muted` | `#566772` | `#9AABB5` | Secondary text |
| `line` | `#DFE5E9` | `#26353F` | Hairlines, input borders |
| `sea` (accent) | `#0B6578` | `#62C6D6` | Primary button, links, route line |
| `soon` / `late` / `done` | `#8A5200` / `#B3261E` / `#1B7443` | `#F0B55A` / `#FF8A80` / `#6FD39B` | Deadline state only, never decoration |

- **Type:** Schibsted Grotesk, one family. Sizes 13 / 15 / 26 (22 on phones). Weights 400, 500, 600. Sentence case everywhere.
- **Spacing:** 4 / 8 / 12 / 16 / 24 / 40. **Radius:** 8px on controls, full on chips and the toast.
- **Motion:** background colour on hover and press only. Nothing animates on its own.

## 2. Information architecture

```
Tern
├─ Chat             (home; onboarding happens here)
├─ Shortlist        (all matched courses, grouped Stretch / Good match / Safe)
├─ Applications     (due this week + every tracked course)
│   └─ Application  (route line, apply link, checklist, course facts, offer and visa steps)
├─ Documents        (uploads and drafts)
└─ Settings         (account, reminders, export or delete my data)
```

- Desktop: left sidebar (232px). Phone: the same four links as a bottom bar.
- Chat can show anything the other pages show (course rows, checklist, timeline), so a user never has to leave it. The pages exist for glancing without asking.
- Plain names replace the internal ones: "Stretch / Good match / Safe" for Ambitious / Target / Safe, "Track" for add to tracker, "reference" for LOR, "statement of purpose" spelled out.

## 3. Key flows

1. **First visit** → sign in → Chat opens with one message from Tern and an upload control: "Upload your CV and I'll tell you where you stand."
2. **Assessment** → Tern replies with two short lists, "Working for you" and "Worth fixing", then asks its first preference question.
3. **Preferences** → one or two questions per turn. Skipping is allowed; Tern states the default it used.
4. **Shortlist** → a progress line ("Checking 42 courses against official pages"), then the three strongest fits inline and a "See all 12 courses" button.
5. **Track** → pressing Track on a course adds it to Applications and builds its checklist. The button changes to "Tracking" and a toast confirms "Added to your applications".
6. **Work the checklist** → each item can open a chat task ("Continue with Tern", "Write the request").
7. **Apply** → "Apply on the university site" opens the official application page in a new tab. Tern never submits.
8. **Offer and visa** → when the status reaches Offer, the checklist gains the offer conditions; at Visa it gains the country's official visa steps.

## 4. Screens and states

| Screen | One job | Default | Empty | Loading / agent working | Error |
|---|---|---|---|---|---|
| **Chat** | Talk to Tern | Conversation, composer pinned to the bottom | First message from Tern plus the CV upload control | Streaming text. Long work shows one progress line that updates in place and ends with a tick. | "Tern couldn't reply. Check your connection and send again." The unsent message stays in the composer. |
| **Shortlist** | Choose courses to track | Rows grouped by fit, filter chips | "No shortlist yet. Tell Tern your countries, subject and budget in chat and your matches will appear here." + "Open chat" | Rows appear as they are verified; the heading counts up ("Checked 18 of 42") | "We couldn't check some courses. They are marked 'Not checked yet' with a link to the official page." |
| **Applications** | See what is due | "Due this week", then every tracked course with its route line | "You are not tracking any courses yet. Open your shortlist and choose Track on the ones you want to apply to." | Skeleton rows (no spinner) | "Your applications didn't load. Try again." + "Try again" |
| **Application** | Finish this application | Route line, apply button, checklist, course facts | n/a | Facts being re-checked show "Checking again…" in place of the date | A fact that fails verification reads "Not checked yet. See the official page." |
| **Documents** | Find a file or draft | Rows with version and date | "No documents yet. Upload your CV to get started." + "Upload a document" | Upload shows progress in the row | "That file is too large. Upload a PDF or Word file under 10 MB." |

**Deadline states.** Default text is ink. Within 30 days it uses `soon`. Past the deadline it uses `late` and the row says "Deadline passed". Colour is never the only signal; the words change too.

**Unverified data.** Never shown as a normal fact. It is muted, has no dotted underline, and reads "Not checked yet. See the official page."

## 5. Components

Generative UI components the chat can render, each built from shadcn primitives.

| Component | Used in | shadcn base |
|---|---|---|
| `Message`, `Composer` | Chat | `Textarea`, `Button`, `ScrollArea` (shadcn chat rules) |
| `ProgressLine` | Chat, Shortlist | text + icon; `aria-live="polite"` |
| `AssessmentLists` | Chat | plain lists |
| `CourseRow` | Chat, Shortlist | `Button` (toggle, `aria-pressed`) |
| `FitFilter` | Shortlist | `ToggleGroup` |
| `RouteLine` | Applications, Application | custom (the one bespoke component); `role="img"` with "Step 2 of 7: Preparing" |
| `ChecklistItem` | Applications, Application, Chat | `Checkbox`, `Label` |
| `Fact` + `SourcePanel` | Application, Chat | `Collapsible` (inline, not a hover tooltip, so it works on touch and keyboard) |
| `CompareTable` | Chat, Shortlist | `Table` in a horizontally scrolling container, up to 4 courses |
| `DocumentRow` | Documents | `Button` |
| `Toast` | global | `Sonner` |
| `Sidebar` / bottom bar | global | `Sidebar` |

Not in the preview yet: `CompareTable`, Settings, sign-in, the offer and visa checklist, and the statement-of-purpose editor.

## 7. Accessibility and quality floor

- Text contrast meets WCAG 2.1 AA in both themes (ink, muted and accent on paper and surface).
- Everything works by keyboard; focus is a 2px accent outline.
- Touch targets are at least 32px high, 36px for buttons.
- Status is never colour-only: the route line has a text label, deadlines change wording.
- Agent progress and toasts are announced (`aria-live="polite"`).
- `prefers-reduced-motion` and `prefers-color-scheme` are respected.
- Phone layout from 360px wide with no sideways scrolling.

### Review status

The preview was checked by screenshot at 1280px and 390px in light and dark themes, and fixed for number spacing, a clipped placeholder and scroll position.
